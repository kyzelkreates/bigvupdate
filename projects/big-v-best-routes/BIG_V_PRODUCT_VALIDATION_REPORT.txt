ARCHITECTURE PATTERN:

  Local-First means: no backend, no auth, no sync — localStorage is the database.
  React state is loaded from localStorage on mount, saved back on every state update.

PART 4 — DATA FLOW (HOW IT ALL WORKS TOGETHER)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TRIP PLANNING FLOW:
  1. User opens app → SafetyDisclaimer if not yet accepted → PlannerDashboard
  2. User selects vehicle type in VehicleForm → vehicleTemplates shows relevant fields only
  3. User fills legal-critical fields (height, weight, etc.)
  4. User enters origin + destination
  5. User clicks "Calculate route"
     App.jsx → handleCalculateRoute()
       → graphhopperClient.calculateRoute()
           → geocodingClient.geocodeAddress(origin), geocodeAddress(destination)
           → VITE_GRAPHHOPPER_API_KEY check → if missing: return { setupRequired: true }
           → GraphHopper API call → decode polyline → normalise route result
       → setState: trip.lastRouteResult, trip.routeStatus ('success' / 'setup_required' / 'error')
       → Auto-runs runComplianceCheck() → setState: compliance
  6. PlannerDashboard renders:
     → RouteStatusBanner (success / setup_required / error / dev_fallback)
     → RouteSummaryPanel (distance, duration, ETA, confidence, Start Navigation CTA)
     → CompliancePanel (score, warnings, evidence, disclaimer)

COMPLIANCE FLOW:
  complianceEngine.runComplianceCheck({ vehicle, trip, restrictions, routeResult })
  → Reads complianceRules.js for UK limits + score deductions
  → Checks legal-critical fields for vehicle type → deducts 14pts each if missing
  → Checks UK dimension/weight limits → deducts 6–10pts if exceeded
  → Checks route result: if setupRequired → override to provider_error status
  → Checks route result: if demoMode/devFallback → deducts 20pts
  → Checks restriction dataset: if empty → deducts 18pts
  → Checks HAZMAT flag → deducts 20pts
  → If missingData >= 3 → score capped at 45
  → Score → advisoryStatus (≥82 suitable, ≥60 needs_review, ≥35 high_risk, <35 missing_data)
  → Always appends COMPLIANCE_DISCLAIMER to warnings
  → Outputs: advisoryStatus, confidenceScore, driverMessage, reportSummary, disclaimer

NAVIGATION FLOW:
  1. RouteSummaryPanel: "Start navigation" → App.jsx.startNavigation()
     → startSessionRecipe(state):
         Builds session object (sessionId, routeSnapshot, vehicleSnapshot,
         complianceSnapshot, warningsSnapshot, gpsStatus, offlineStatus)
         Sets navigation.status = 'active'
         Sets navigation.lockedVehicleId, navigation.lockedRouteId
         Sets app.mode = 'navigation'
         All written to SSOT via updateState()
  2. NavigationPWA renders → NavigationMapShell
  3. NavigationMapShell:
     → Checks MAP_STYLE_CONFIGURED — if false: shows setup-required panel
     → loadMapLibre() → createMap() → map.on('load') → setRouteLayer(polyline)
     → Simulated GPS timer → interpolateAlongPolyline() → moveVehicleMarker() + followCamera()
     → If real GPS: locationService.watchPosition() → updateGpsRecipe() → SSOT
     → NavInstructionCard: instruction text, remaining distance/time, ETA, voice, stop
  4. Stop navigation → stopSessionRecipe() → clears lock, sets status='stopped'

NAVIGATION LOCK:
  When navigation.status === 'active' or 'paused':
  → navLocked = true
  → VehicleForm: all fields disabled, locked badge shown
  → PlannerDashboard: Calculate route / Run Compliance / trip inputs all disabled
  → Route mode selector disabled
  → Vehicle type selector disabled
  User must press "Stop navigation" before editing anything
